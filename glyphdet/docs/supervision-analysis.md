# 监督信号审计报告：loss 与检测性能为何脱节

日期：2026-09-11。起因是两个观察：① `runs/mvp_100k_hardneg`（v1）loss 明显高于 `runs/mvp_v2`，但 v1 检测性能反而更好；② 怀疑监督让模型"只看单字图形、不看整串"。两个观察都成立，且指向同一组设计缺陷。

## 1. Loss 组分对质（权重两边相同：match 1.0 / reg 2.0 / cen 0.5 / margin 0.5）

| 组分（末轮均值） | v1 hardneg ep40 | v2 ep26 |
|---|---|---|
| match（focal 逐格分类） | **0.0054** | **0.076**（14 倍） |
| reg（DFL+CIoU） | 0.477 | 0.408 |
| cen（centerness BCE） | 0.611 | 0.634 |
| margin（近邻排序） | ≈0 | ≈0 |
| n_pos / batch | ~300 | ~650 |
| 总 loss | 1.293 | 1.173 |

总 loss 口径一致（同权重同公式），v2 更低**完全来自 reg 项的下降盖住了 match 项 14 倍的上涨**。而 reg 低是假的，见下。

## 2. 断点一：回归监督被钳位，loss 降 ≠ 框变好（已修复）

- `build_targets` 把 ltrb 目标 clip 在 `reg_max-1.01 = 6.99` 格，decode 上限同理 `7×stride` px/边。
- v2 按**字高**分配层级（s4: h<28、s8: 28~56、s16: ≥56），**不看宽度**。每级可表达的最大框宽只有 56 / 112 / 224 px，而 9 位取件码串宽 p50 就有 101~210px。
- 实测（`datasets/mvp`）：**68% 目标的宽度方向被钳**（s4 91.4%、s8 77.1%、s16 40.8%）。DFL 去拟合一个被截断的确定性目标，当然拟合得快——reg loss 低是"目标被改简单了"，不是框变好了。
- 这锁死了 recall@0.5 天花板（钳位后完美居中的 IoU 上界 p50 仅 0.56/0.77），v2 ep25 的 recall@0.5(0.466)≪recall@0.3(0.569) 即由此而来，并非"未收敛"。
- v1 免疫：maxd 分配的层级边界（64=8×8, 128=8×16）恰好对齐 reg_max×stride，分配到的层级天然能表达框的最大边。

**修复（v2.2，已落地）**：`reg_max` 8→24；分配加宽度护栏 `level_for_box`（字高定级，中心带最远格点 0.75w 超过 `(reg_max-2)×s` 自动上浮）。验证：train/val 钳位 0%，上浮 9.2%，200 张 val reg 实测最大 21.51 格 < 22.99 clip 线，零静默丢目标。

第一版护栏用 w/2 判定是错的——中心带（CENTER_SHRINK=0.25）内最右格点距左边 0.75w，验证脚本当场抓到（16→24 的由来）。

## 3. 断点二：match 是逐格图形分类，不奖励"看全体"

match 标签是**纯位置先验**（目标框中心 50% 区域=1，与内容无关），focal 奖励的是"这片纹理像字"。两条证据通道都撑不起整串核验：

- **cos 路径**：单格特征 × 整串池化嵌入。细级别单格的有效感受野远小于 150~400px 的整串宽度，物理上看不全，最多编码"局部纹理与模板中某字相似"。
- **xcorr 路径**：模板被双线性压扁到固定 (sh,sw)，与场景里自然宽高比的串做定窗相关；长串只覆盖局部；fuse 是 1×1 点卷积，没有沿串方向的空间整合。

实锤链：levelstat 显示 v1 终局 **86% 的检出发生在仅余弦级别**，唯一带 xcorr 的 s8 只抓 19%——模型实际是个"余弦相似度检测器"，xcorr 是装饰；fppeek 显示 fp 全是**高分近邻串**（73853 打到 0.86）——单字个个像=高分，整串不等不扣分。这两个现象是同一病根：**监督从未把"整串全等"作为必要条件写进结构或标签。**

## 4. 断点三：margin 是唯一"看全体"的压力，但稀疏且会消失

- margin 只作用在**训练过的** distractor 中心（稀疏点约束）；
- 判定宽松：`relu(max_neg − mean_pos + 2.0)`，logit 差 2 即满足（sigmoid 0.88 vs 0.12 的间隔），不满足"逐字全等"的语义；
- 训练后期归零——训练分布上被记忆性满足，泛化不成"逐字核验"算子。held-out 近邻串（换字体/换组合）照样打高分。

## 5. 为什么 v1 loss 高却性能好

- 口径：v2 网格更细，n_pos 翻倍（~650 vs ~300），同样的 loss 被更多正样本摊薄；
- 难度：粗网格上背景与字的逐格区分本来就更容易，match 收敛到 0.005 很自然；s4 细网格上 4px 粒度的背景纹理大量类字，match 0.076 不代表更差；
- 一致性：v1 的 reg 监督自洽（无钳位），loss 的每滴下降都真实转化为框质量；v2 的 reg 下降部分流向了错误目标。
- **结论：跨 run 比 loss 总量没有意义，要盯组分与评测口径的一致性。**

## 6. 附带发现：centerness 无 headroom（已修复，toy 验证定案）

cen BCE 长期 0.61~0.63，初判"零信息"。toy 验证（tools/cenprobe.py，v1 终局模型 + mvp4/val 同分布 100 张，CPU）修正为精确结论：

| decode 方式 | AUROC |
|---|---|
| 乘 cen（原设计） | 0.9515 |
| 不乘 cen | 0.9481 |
| 乘 oracle cen（GT 几何真值） | **0.9320** |

- cen 实际学到了弱信号（预测 vs GT Pearson r=0.333，std 0.097 vs GT 0.280），但只值 +0.003 AUROC；
- **oracle cen 比不乘还差** → 几何 centerness 概念在本任务天花板为负：长条框的两端格恰是最具判别力的位置，几何中心度反而惩罚它们；
- top-1 格点 94/100 变化但指标不动 → 它只是个噪声级重排因子。

**修复（v2.2，已落地）**：HeadV2 砍掉 cen 通道（输出 2+4·reg_max → 1+4·reg_max），decode/eval 按通道数自动判别新旧布局（旧 v1 checkpoint 仍可评估），train 跳过 cen loss。冒烟：三级输出 97 通道、reparam 等价（diff 8e-7）、双布局 decode 正常、compute_loss 正常。排序先验若需要，留 v3 用学习型 soft-score，不用几何先验。

## 7. 治"不看全体"的候选方案（按推荐顺序）

1. **A. 结构性 per-char 聚合（推荐作 v3 核心）**：模板不再全局池化成单向量，改为逐字符嵌入序列；整串分 = 逐字匹配的 min/带权聚合（最弱字符决定）。把"逐字核验"写进架构，不靠 loss 教，单字像≠整串像。
2. **B. ROI 级整串判别头**：候选框内池化证据做 0/1 等式监督——二期 TextProposal+Verifier 的轻量前置。
3. **C. 数据加量**：单字变异 hard-neg 继续加（v6 已有），但单靠数据会被记忆捷径吃掉，必须配 A/B。
