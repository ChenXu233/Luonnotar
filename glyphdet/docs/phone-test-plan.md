# 手机真机测试计划（glyph_det v2.2 首装）

对象：`build/app/outputs/flutter-apk/app-debug.apk`（254.6MB debug，双 ABI，paddle+glyphdet 双引擎都在包里）
被测管线：camera2 NDK → letterbox 416² → ncnn Vulkan → C++ decode（thr0.5 / NMS0.4 / max20）→ Dart 轮询（100ms）→ 高亮 overlay。
前置：手机开 USB 调试，`adb devices` 可见。全程命令在仓库根目录执行。

## 0. 安装与基线

```bash
adb install -r build/app/outputs/flutter-apk/app-debug.apk
# 另开终端持续抓性能日志：
adb logcat -s GlyphDetPerf GlyphDet
```

| 项 | 记录 |
|---|---|
| 安装是否成功 | |
| 首次冷启动→相机画面出现耗时 | |
| Vulkan 首次加载（着色器编译）耗时（logcat） | |
| 二次冷启动耗时（着色器缓存后） | |

若 Vulkan 加载 >10s 或崩溃：改 `lib/ocr/glyph_det_service.dart` 的 `loadModel(cpugpu: 0)` 走 CPU 对比，两档数据都记。

## 1. 管线性能（核心验收）

空场景对准货架/墙面，不输入取件码，直接读底部调试行（`FPS + 推理ms`）与 logcat：

| 场景 | infer_ms EMA | FPS | 备注 |
|---|---|---|---|
| 静止空场景 | | | |
| 静止有文字场景（书脊/货架标签） | | | paddle 时代病根：遇文字延迟飙升，重点看是否复现 |
| 缓慢平移 | | | |
| 连续 5 分钟（热节流） | | | 第 1/3/5 分钟各记一次 |

参考门槛：infer_ms ≤ 30ms（Vulkan）/ ≤ 60ms（CPU），FPS ≥ 20。不达标 → 开 fp16 重对拍再来一轮。

## 2. 检测正确性（功能验收）

准备：在电脑屏幕/另一台手机屏幕上显示几组取件码大字（黑字白底，无衬线字体），或打印纸条。每组记录：是否锁定、锁定耗时、top1 分数（logcat/调试行）。

| 用例 | 预期 | 结果 |
|---|---|---|
| 输入与画面一致的码（如 24-6-1234） | 1-2 帧内锁定，框贴合整串 | |
| 距离拉远（字高 ~16-24px 等效，约一臂距离） | 仍锁定（v2.2 训练覆盖 16-64px 字高） | |
| 倾斜 ±15°、侧向透视 | 仍锁定 | |
| 画面里无该码 | 无锁定（底部持续"正在寻找"） | |
| **近邻干扰**：画面是 08534，输入 08504 | 不锁定或分数明显低（v2.2 已知 fp=0.10 病根，此条记录实际严重度） | |
| 画面多个码并排，找其中一个 | 锁定正确那个 | |
| 弱光 + 闪光灯 | 锁定 | |
| 手持行走移动中锁定 | 记录成功率/延迟（v2 的分立帧识别，预期移动中断续，如实记录） | |

## 3. 域差专查（mask 渲染）

App 侧 mask 是 Flutter 段落渲染近似训练侧 PIL `render_mask`，存在域差风险。专查：

- 输入码后若静止近距离都锁不上 → 大概率 mask 域差。对照实验：插件 example（`vendor/glyph_det/example`，同一份 mask 渲染代码）复现；再把训练侧 `render_mask` 生成的 PNG 投到屏幕上用 example 扫，两方向定位是渲染端还是模型端问题。
- 最长码边界：10 字符（如 25-17-10240）能否锁定（mask 等比压缩极限）。

## 4. ARM decode 对拍（可选，异常时再做）

宿主机对拍已 PASS（tests/parity）。真机侧仅在"宿主机能锁、真机同画面锁不上"时做：
从 logcat 抓一帧原始输出张量 dump（需临时在原生层加 dump 开关），拿宿主机 `core/decode.py` 跑同一张量比对框差异，预期 ≤1px 级。
